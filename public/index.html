05 / FIELD NOTES
What counts
as a fix?
A short guide to REGRA’s decisions and the limits of its evidence.

      
01
First, prove the failure.
Choose an input and the result your application should produce. The original code must fail this new test, while its existing behavior checks still pass.
02
Give both versions the same contract.
Load a repair, edit the code, or draft one with a local model. REGRA runs the expected behavior against the original and candidate, including previously saved lessons.
03
Keep the result honest.
Verified
The recorded gates passed. A lesson is retained.
Rejected
The repair fails one or more behavior checks.
Inconclusive
Reproduction, execution or repeatability could not establish a usable result.
04
Know what was checked.
Three repeat runs sample consistency. Passing tests do not establish that a program has no bugs. Expectations need review, and evidence applies to the recorded code and runtime.
This beta runs reviewed, standalone synchronous JavaScript with JSON inputs and outputs or named errors. Whole repositories, Python and browser tests are future work. The local runner is not a security sandbox for hostile code.
